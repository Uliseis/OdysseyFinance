# Decisions

Settled choices. Don't reopen one by drifting from it in code. Add a new entry that supersedes it, and mark the old one.

Format: **decision**, why, and when it's worth revisiting.

---

### D1. Native iOS app, no server
**Decision.** A native SwiftUI app with all logic on the device. No backend and no account system; the iCloud account is the boundary.
**Why.** Single user; bank data shouldn't sit on a server the app has to secure.
**Revisit when.** A second user or a web client is needed.

### D2. SwiftData locally, CloudKit private database via `CKSyncEngine`
**Decision.** SwiftData `@Model` types as the store, synced through a hand-rolled `CKSyncEngine` layer, not `NSPersistentCloudKitContainer`.
**Why.** Explicit control over conflict resolution, deduplication and push timing (see D3, D4).
**Revisit when.** `NSPersistentCloudKitContainer` gains custom conflict policies.

### D3. Conflict policy: last writer wins, except manual categories
**Decision.** Records resolve by `updatedAt`. A transaction whose category was set by hand (`categorySource == .manual`) keeps that category against any non-manual write.
**Why.** A bank re-sync on another device must never undo a choice made by hand.

### D4. Composite uniqueness in code, never `#Unique`
**Decision.** `Transaction(account, externalId)` and `FxRate(date, currency)` are deduplicated in `CoreSync` (`CompositeDedupe` and the pull pipeline). Enforced by `scripts/check-repo.sh`.
**Why.** `#Unique` resolves conflicts by a silent, non-deterministic upsert that rewrites the row's `id`. That breaks the `CKRecord.recordName == id` invariant and the deterministic winner across devices.
**Revisit when.** SwiftData lets the caller choose which row survives.

### D5. Deletes through SwiftData delete rules
**Decision.** Bare `ctx.delete(model)`. Cascades and nullifies come from `@Relationship(deleteRule:)`, including the recursive ones (`Transaction.routedFromTx`, `Category.parent`). `CascadeTests` guards all four delete shapes.
**Why.** The iOS 18 bug that needed explicit cascade helpers is fixed on iOS 26.
**Revisit when.** `CascadeTests` fails on a new SDK: restore explicit helpers.

### D6. Money is `Decimal`, EUR first, ECB rates
**Decision.** Amounts are `Decimal` in storage and logic (matching the original `numeric(p,s)` columns). Every transaction keeps its original currency, its EUR amount and the ECB rate used. Charts convert to `Double` only to plot.

### D7. Enable Banking on the device
**Decision.** Enable Banking (PSD2) is called straight from the app. RS256 JWTs are signed on the device with the application key, which is stored in the iCloud Keychain. The bank-consent redirect is an `https` URL on the app's associated domain, served as static files from `Vercel/`.
**Why.** There is no server to hold a key (D1), and a single-user app never ships the key inside a distributed binary.
**Revisit when.** The app is distributed to other people.

### D8. Spaces, shared expenses and investments
**Decision.** Any number of spaces, with cross-space transfer invariants. Shared expenses are kept. Investments are tracked per account as valuation snapshots plus a cost-basis anchor, with live values from Trading 212 and CoinGecko. There is no per-instrument holdings model.
**Revisit when.** Per-position reporting (lots, dividends per instrument) is needed.

### D9. Category source is never null
**Decision.** `categorySource` is a non-optional `CategorySource` (`bank`, `rule`, `manual`). Rows imported without one were backfilled to `.bank`.

### D10. The web app is a frozen spec
**Decision.** `Spec/` is a read-only snapshot of the original Next.js app, kept as the porting reference. It was migrated once (`Tools/`); the web app is decommissioned. Enforced for PRs by `scripts/check-repo.sh`.

### D11. Generated, not committed: Xcode project and icon PNGs
**Decision.** `OdysseyFinance.xcodeproj` is generated from `project.yml` by XcodeGen and ignored. The app icon PNGs are generated by `design/app-icon/make_icon.py` and committed; edit the script, never the PNGs.

### D12. Public repository with no personal data (2026-10-18)
**Decision.** The repository is public. No real balances, transactions, merchants, people, account identifiers or record counts appear in code, fixtures, commit messages or PR descriptions. Keys, statements and stores never enter git.
**Why.** Pushed content is archived by third parties within minutes and can't be recalled. The history was rewritten once to remove such data.
